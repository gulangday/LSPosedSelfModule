# _UPDATE · 规则维护流程

本文件只在收到「添加 / 修改 / 废弃规则」指令时读取，不参与日常检索。

## 触发词

用户说「加条规则」「补一条坑」「更新 skill」「把这个问题记进去」「废弃 X1」等。

## 添加一条新规则（8 步）

1. **判重**：`grep -n "<症状关键词>" SKILL.md`，已有同现象 key 就并入那一条，不新建。
2. **分配编号**：取该字母现有最大编号 +1（如 B9 → B10）。空缺号不复用，编号永不重排。
3. **选文件**：按现象归入 15 个主题之一；都不贴切时新建 `references/<字母>-<主题>.md`，并在 SKILL.md 加分组标题。
4. **写详情**：在目标文件末尾追加，严格用 5 段模板：
   ```markdown
   ## <key> · <八到十五字标题>

   - **现象**：用户能看到什么。
   - **根因**：机制层面的原因，不写"手滑""忘了"。
   - **正确做法**：具体到函数名 / 参数 / 命令。
   - **自查项**：
     - [ ] 一条可验证的检查
   - **关联**：其它 key 或"无"
   ```
5. **写索引**：同一轮在 SKILL.md 对应分组末尾加一行，格式严格为：
   `<key> <症状关键词，用、分隔>｜<根因要点>｜<一句话对策>`
6. **记版本**：`CHANGELOG.md` 顶部追加一行 `## v0.x.y · YYYY-MM-DD` + 新增 key 列表。
7. **自校验**：`pwsh -File install.ps1 -Verify`，必须 0 报错。
8. **回报**：告诉用户：新 key、落在哪个文件、版本号、是否需要重装（copy 模式需要，link 模式不用）。

## 修改已有规则

- 只改该 key 小节的正文，**不改编号、不改文件、不改标题**。
- 若现象变了但本质相同：保留原 key，在标题后加备注。
- 若本质已不同：废弃旧 key（见下），新建一条并在关联里互指。

## 废弃一条规则

1. 详情标题改成 `## <key> · ~~<原标题>~~（已废弃 YYYY-MM-DD）`，正文保留。
2. 索引行前加 `~~` 并移到该分组末尾，不删除——历史引用仍能定位。
3. CHANGELOG 记一条"废弃"。
4. 编号继续保留，不得被新规则复用。

## 硬约束

- 禁止只改详情不改索引（反之亦然），`-Verify` 会报出来。
- 禁止把两条不同现象合并成一个 key 省事。
- 禁止写没有"自查项"的条目。
- 新增后单条仍须 ≤ 12 行；超了就拆成两条。
