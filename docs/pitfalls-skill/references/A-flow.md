# A 流程协作

## A1 · 列完清单没等确认就动手

- **现象**：刚给出清单或方案，紧接着就改了文件、跑了构建。
- **根因**：把"列清单"当成走场，省略等待确认；或把用户的提问当成批准。
- **正确做法**：清单末尾显式写"确认后开始"；只有收到「开始 / 可以 / 做吧 / 动手 / ok」才动文件。只读检查不受限。
- **自查项**：
  - [ ] 本轮是否发生了写文件 / 构建 / 装机？
  - [ ] 用户消息里是否有明确的开始指令？
- **关联**：A4

## A2 · 规则写进 README 以为会遵守

- **现象**：约定写在 README 或 docs 里，agent 实际不遵守。
- **根因**：README 不会自动进入模型上下文，只有 AGENTS.md 与 skill 会被注入。
- **正确做法**：硬约束写 AGENTS.md；按需查阅的领域知识写 skill（索引 + 详情）。
- **自查项**：
  - [ ] 新增的硬规则有没有落点？
  - [ ] 是否只写在了 README 里？
- **关联**：无

## A3 · 批量替换写坏中文

- **现象**：批量替换后中文变乱码（如 `鐢?`），或编译报 unresolved reference。
- **根因**：Windows 控制台与 PowerShell 默认按 GBK 解码，读写 UTF-8 无 BOM 源码时编码错位；sed 同理。
- **正确做法**：一律用 edit / write 工具逐处修改；确实要脚本时显式 `-Encoding UTF8`，并先备份。
- **自查项**：
  - [ ] 是否用了 `pwsh -replace` 或 sed 改源码？
  - [ ] 改动处的中文是否正常？
- **关联**：无

## A4 · 删除清空没确认就执行

- **现象**：用户点一下就删掉了日志、规则或目标应用。
- **根因**：删除回调里直接调用删除接口，没有二次确认。
- **正确做法**：删除 / 清空 / 覆盖一律走 `ui.dialog` 二次确认，文案写明删什么、能否恢复。
- **自查项**：
  - [ ] 破坏性操作前是否有确认弹窗？
  - [ ] 弹窗文案是否说明影响？
- **关联**：A5、H7

## A5 · 点"取消"反而执行了删除

- **现象**：删除确认框点了取消，数据仍然被删。
- **根因**：写成了 `ui.dialog(...) { 删除() }`，尾随 lambda 绑到 `onConfirm`（`UiKit.dialog` 签名里 onConfirm 在 onCancel 之前）。
- **正确做法**：显式命名参数 `onConfirm = { }`、`onCancel = { }`，不依赖参数顺序。
- **自查项**：
  - [ ] 每个 dialog 调用是否都用了命名参数？
- **关联**：A4
