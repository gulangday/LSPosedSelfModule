# C Root 与权限

## C3 · App 请求不到 root

- **现象**：`su -c` 无输出或超时，但设备确实已 root。
- **根因**：Magisk / Shamiko 对模块隐藏了 su；或 su 不在 PATH 里。
- **正确做法**：`RootShell.suExists()` 多路径探测 + `isToolError()` 过滤错误输出；探测失败时提示改用 Shizuku（`MainActivity` 第 196 行）。
- **自查项**：
  - [ ] 是否做了多路径探测？
  - [ ] 失败提示是否给了替代方案？
- **关联**：C7

## C4 · 自启动显示假"已开启"

- **现象**：权限页显示"自启动已开启"，实际没开。
- **根因**：系统没有查询自启动状态的公开接口，只能引导用户去设置页开。
- **正确做法**：不做状态展示，只做跳转引导卡片；文案写"建议开启（非必需）"。
- **自查项**：
  - [ ] 是否伪造了无法查询的状态？
- **关联**：H5

## C5 · 常驻通知不显示、服务被限制

- **现象**：前台服务被系统杀，或通知不出现。
- **根因**：Android 13+ 未授予 `POST_NOTIFICATIONS`；或通知渠道被禁用。
- **正确做法**：权限页检测 `POST_NOTIFICATIONS`（`PermissionsScreen` 第 124 行）并引导授权；前台服务用低优先级渠道。
- **自查项**：
  - [ ] 是否检查了通知权限？
  - [ ] 通知渠道是否低优先级？
- **关联**：无

## C7 · su 路径写死导致探测失败

- **现象**：部分机型明明有 root，`suExists()` 却返回 false。
- **根因**：不同设备 su 在 `/system/bin`、`/system/xbin`、`/sbin`、Magisk 自带路径等不同位置。
- **正确做法**：遍历候选路径探测，并用 `isToolError()` 过滤 "not found / permission denied" 类输出（`RootShell` 第 37-42 行）。
- **自查项**：
  - [ ] 候选路径是否 ≥ 3 个？
  - [ ] 是否过滤了工具自身错误输出？
- **关联**：C3
