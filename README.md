# 自用模块（LSPosed）

一个按应用配置的 Android 增强模块：**拦截烦人的更新弹窗 / Toast**，也可以在目标应用里显示自定义的底部提示。

适用于已 root（Magisk）或使用 Shizuku 的设备，需要 LSPosed 框架。

## 功能

- **弹窗拦截**：按关键字或已学规则拦截 Dialog（更新提示、活动弹窗等），支持悬浮窗点选、自动拦截、拦截截图留档。
- **Toast 拦截**：按关键字拦掉目标应用自己弹的 Toast。
- **弹窗提醒**：在目标应用底部显示一条自绘提示，文字、显示时长、淡出时长都可调。
- **三层开关**：主页「模块已启用」→ 功能开关 → 功能内选项，全部按应用独立配置、默认关闭。
- **多目标应用**：每个应用独立配置，长按卡片可移除。

## 使用流程

1. 安装 APK，在 LSPosed 里启用「自用模块」，并勾选目标应用的**作用域**
2. 打开模块，添加目标应用
3. 在主页把该应用的「模块已启用」打开
4. 进入「功能」，按需开启拦截弹窗 / 弹窗提醒
5. 重启目标应用后生效

> 作用域和主页开关是两件事：作用域没勾，模块不会被注入；模块没启用，功能不会执行。

## 构建

需要 JDK 17 与 Android SDK 35。

```bash
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

## 工作原理

- 模块通过 LSPosed 注入目标应用进程，hook `Dialog` / `Toast` 的显示
- 功能开关、规则、关键字等数据写在**目标应用自己的数据目录**，hook 直接读取，不依赖模块进程
- 模块界面通过 Root / Shizuku 通道读写这些文件；非 Root 模式下相关功能不可用

## 已知限制

- 只能拦截 Android 的 `Dialog` / `Toast`：Unity、Flutter 等自绘界面识别不了
- 只能拦目标应用自己弹的；其他应用、系统 UI 的弹窗和 Toast 拦不到
- 直接 `su` 被隐藏（Shamiko / DenyList / 白名单模式）时，需要改用 Shizuku 模式
- 厂商 ROM 的自启动权限没有公开查询接口，模块只能引导用户去系统设置开启
