# D 配置存储与解析

## D1 · 模块配置读不到或重启后丢失

- **现象**：模块里的配置（弹窗文案、显示时长等）在目标进程读不到；或改完重启回到默认。
- **根因**：数据存在模块自己的 SharedPreferences，targetSdk 30+ 下目标应用看不到；且 SP 文件默认 0600，LSPosed 文件服务也可能读不了。
- **正确做法**：hook 要读的数据写目标应用 `/data/data/<pkg>/files/*.conf`；模块 UI 侧需要 XSharedPreferences 读的，用 `PrefsPermission.makeWorldReadable()` 把 xml 设成 0644。
- **自查项**：
  - [ ] 这份数据是给 hook 读还是给 UI 读？
  - [ ] 路径是否在目标应用目录下？
- **关联**：D6、PrefsPermission

## D2 · 读出来是 `1@@M`

- **现象**：解析出的值尾巴多了 `@@M`，功能判断错乱。
- **根因**：`printf '%s'` 写入的文件末尾没有换行，下一次 `echo '@@M'` 会黏在最后一行。
- **正确做法**：写入带换行（`printf '%s\n'`）；读取时每个 `cat` 后面补一个 `echo` 隔离分段（`TargetFiles.load` 里的做法）。
- **自查项**：
  - [ ] 写文件是否带结尾换行？
  - [ ] 拼接命令里每个 cat 后是否有 echo？
- **关联**：D3

## D3 · 显示未开启但功能正常

- **现象**：UI 显示没开，实际 hook 生效。
- **根因**：与 D2 同源，`1@@M` 被当成非 "1"；或读到的是过期缓存。
- **正确做法**：修解析（trim + 分段）；写操作成功后 `TargetFiles.invalidate(pkg)`。
- **自查项**：
  - [ ] 解析是否做了 trim？
  - [ ] 写后是否 invalidate？
- **关联**：D2、F4

## D4 · 30 秒内全显示未开启

- **现象**：刚进页面所有功能都显示未开启，等 30 秒后才正常。
- **根因**：把失败结果（Shizuku 未绑定、命令超时返回空串）也写进了缓存。
- **正确做法**：只有输出包含 `@@F` 标记才写缓存（`TargetFiles.load`），失败不缓存。
- **自查项**：
  - [ ] 缓存写入前是否判断了成功标记？
- **关联**：D7、F4
