# F 性能与主线程

## F1 · 冷启动 4.9 秒

- **现象**：打开模块要等近 5 秒才出内容。
- **根因**：主页渲染前同步等 Shizuku 绑定，或同步跑 root 命令。
- **正确做法**：先 `TargetFiles.peek()` 用缓存渲染，再后台 `load()` 完成后 `refresh()`（`HomeScreen` 的差异刷新）。
- **自查项**：
  - [ ] 首帧是否用了缓存数据？
  - [ ] 主线程是否有阻塞调用？
- **关联**：F2、F3

## F2 · 页面卡顿

- **现象**：滚动或切换页面掉帧。
- **根因**：每渲染一个字段就跑一次 IPC。
- **正确做法**：合并命令 + TTL 缓存（同 D7）；状态对象复用，不重复 new。
- **自查项**：
  - [ ] 一次渲染里有几次 IPC？
- **关联**：D7、C6

## F3 · ANR 或掉帧

- **现象**：点按钮后界面卡死几秒，甚至 ANR。
- **根因**：主线程执行 root 命令或文件 IO。
- **正确做法**：后台线程执行，结果回主线程更新；按钮先改本地状态再后台写。
- **自查项**：
  - [ ] 主线程是否有 exec / readText / writeText？
- **关联**：F1

## F4 · 缓存太旧导致显示不一致

- **现象**：改完开关回到列表，仍显示旧状态。
- **根因**：写成功后没有失效缓存。
- **正确做法**：每个写操作成功后 `TargetFiles.invalidate(pkg)`。
- **自查项**：
  - [ ] 所有写路径是否都调了 invalidate？
- **关联**：D3、D4

## F5 · 无限刷新

- **现象**：页面一直闪，CPU 占用高。
- **根因**：后台刷新回调里没有差异判断就 `refresh()`，刷新又触发后台读取。
- **正确做法**：只在"新值 != 当前显示值"时刷新；刷新前加 in-flight 标记防重入。
- **自查项**：
  - [ ] 是否有差异判断？
  - [ ] 是否有重入保护？
- **关联**：B8

## F6 · 主页刷新几十条 root 命令

- **现象**：目标应用一多，主页每次刷新要一两秒，手机发烫。
- **根因**：逐包 `TargetFiles.load()` 各跑一条 shell；作用域又逐包复制整个 `modules_config.db`。
- **正确做法**：作用域用 `LsposedScope.isInScopeBatch()`：整库只复制一次、一条 SQL 取回全部包。目标应用文件读取**保持逐包**；若要改批量，必须先确认该机器 su 能跑批量脚本并用顺序语句展开（见 F14），失败要能回退逐包。
- **自查项**：
  - [ ] 有没有把整库复制放在循环里？
  - [ ] 批量读取换上去之前，在真机验过吗？
- **关联**：F2、F14、D8

## F7 · 进功能页卡几秒

- **现象**：点进净化 / 翻译 / 去广告页，先停住一到几秒才出内容。
- **根因**：`render()` 里同步 `TargetFiles.load()`，缓存过期时主线程等 6 秒超时的 shell。
- **正确做法**：首帧只 `peek()`；为空就渲染「正在读取…」并 `TargetFiles.loadAsync()`，完成回调 `host.refresh()`。失败要给短缓存，否则占位永远不消失。
- **自查项**：
  - [ ] `render()` 里还有 `TargetFiles.load()` 吗？
  - [ ] 读取失败有兜底显示吗？
- **关联**：F1、F3、F5

## F8 · 点开关顿一下

- **现象**：点模块开关或悬浮球开关，界面明显顿一下才变色。
- **根因**：点击回调里同步 `Features.setRemote()`（读一次 + 写一次 root 命令）。
- **正确做法**：先按目标状态改 UI 并返回 true（`ui.statusChip` 会保留），后台线程写；失败再 `refresh()` 回滚并 toast（`ScreenHost.setFeatureAsync`）。
- **自查项**：
  - [ ] onChange 里还有 `RootShell.exec` / `setRemote` 吗？
- **关联**：F3、F4

## F9 · hook 热路径反复读配置

- **现象**：开了模块后目标应用发热、滑动变卡。
- **根因**：`Features.isOn` / `Keywords.load` / `loadPickMode` 每次调用都读文件解析；`Dialog.show`、Toast、DNS 每个请求都会触发。
- **正确做法**：整份配置缓存 + 1~2 秒 TTL，过期先比 `lastModified` / `length` 再决定重读；本进程写成功后 `invalidate()`。注意 hook 进程收不到 UI 的写通知，只能靠 TTL / 文件戳。
- **自查项**：
  - [ ] 热路径（Dialog / Toast / DNS / 每帧）里还有 `readText()` 吗？
- **关联**：F2、D1

## F10 · 列表每次查 PackageManager 和图标

- **现象**：主页 / 选择器重新打开或滚动时掉帧，图标出现慢。
- **根因**：单卡 4 次 `getPackageInfo` / `getApplicationInfo` / `getApplicationIcon`，每次重绘重新解码图标；选择器在主线程扫全部已安装应用。
- **正确做法**：一次 `getPackageInfo` 拿 label / version / icon，存 `LruCache`；启动器列表后台加载 + 缓存，首帧显示「读取中」。
- **自查项**：
  - [ ] 单卡 PackageManager 调用次数？
  - [ ] 图标是否走缓存？
- **关联**：F2、F7

## F11 · 切回模块就整页重建

- **现象**：从目标应用切回模块，主页白一下，之后发热。
- **根因**：`onResume` 无条件 `renderPage(HOME)`，重建全部卡片并再触发一轮读取。
- **正确做法**：加时间节流（15~30 秒内不重建）；页面内操作自己 `refresh()`。
- **自查项**：
  - [ ] `onResume` 是否无条件重渲染？
- **关联**：F5

## F12 · 扫描整棵 View 树却没规则可用

- **现象**：没建规则时目标应用仍卡；弹窗 / 翻译每次全树遍历。
- **根因**：净化 / 翻译 / 弹窗评估无条件遍历，规则为空也要走到底才发现没事做。
- **正确做法**：按规则类型预筛（无 text 规则就不取文本、无 id 规则就不查资源名）；规则文件戳不变就跳过重读；弹窗无规则 + 无关键字 + 非自动模式时只挂点选入口并恢复可见。
- **自查项**：
  - [ ] 遍历前是否检查「有没有事可做」？
  - [ ] 跳过路径是否补了必需副作用（例如恢复 alpha）？
- **关联**：F3、E3

## F13 · 读取失败被当成未启用

- **现象**：开关明明开着、功能也正常，模块界面却显示全部未启用；切页回来或重启后更明显。
- **根因**：读取失败时把空状态写进了 `peek` 能看到的缓存，而 `peek` 不看年龄，一次瞬时失败就被固化；后台差异刷新又判定「没变化」，永远不会自愈。
- **正确做法**：失败只记 `failedAt`（5 秒内不重复发命令），**永远不进 cache**；界面用 `hasState` / `failedRecently` 区分「读取中 / 读取失败 / 未启用」，失败给重试入口；后台批量读取失败重试两轮再报。
- **自查项**：
  - [ ] `peek` 里的值是否只来自带 `@@F` 的成功读取？
  - [ ] 没读到时界面显示的是「读取中 / 读取失败」而不是「未启用」？
- **关联**：D4、F4、F5

## F14 · 批量脚本在部分 su 上失效

- **现象**：一条命令批量读多个目标应用时全部读不到，改成逐包读取就正常。
- **根因**：`for P in ...; do ... done` 经 `su -c` 多层引号后，部分 su / 魔改 ROM 直接报错或返回空，整批拿不到 `@@PKG` 标记。
- **正确做法**：把循环展开成顺序语句——每个包 `D=/data/data/<pkg>; echo "@@PKG <pkg>"; <读取脚本>`——仍是一条命令；同时保留「批量失败回退逐包」，回退在第一个包失败时中止。
- **自查项**：
  - [ ] 批量命令是否只依赖 `;` 和变量赋值，不依赖 for / 函数？
  - [ ] 批量失败有回退路径吗？
- **关联**：F6、D2

## F15 · 关掉开关又变回开启

- **现象**：点关闭后界面变成未启用，切页或过一会儿又变回已启用（有时文件已经是 0）。
- **根因**：为了提高响应把开关改成「先改界面、后台写」，而后台读取可能在写入前就把旧值读走并写入缓存；写完虽然 invalidate 了缓存，旧读取晚到又把它盖回去。
- **正确做法**：二选一——同步写（写完再切界面、失败不切）；或异步写 + 版本号守卫：写成功后才 `invalidate`，`invalidate` 自增版本号，读取完成时版本变了就丢弃结果。本项目采用后者。
- **自查项**：
  - [ ] `invalidate` 是不是在写入**成功后**才调？
  - [ ] `load` 是否比对了开始/结束时的版本号再写缓存？
- **关联**：F4、F5、F8
