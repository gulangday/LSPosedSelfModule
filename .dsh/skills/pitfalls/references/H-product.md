# H 功能语义与产品规则

## H1 · 新功能默认就开着

- **现象**：装上模块，新功能自动生效，用户没同意。
- **根因**：默认值写成了 true。
- **正确做法**：默认全关（`Features.isOn` 在文件不存在时返回 false），按应用显式开启。
- **自查项**：
  - [ ] 新功能默认值是否为 false？
- **关联**：H2

## H2 · 主页开关语义混乱

- **现象**：用户以为主页开关控制拦截，实际控制的是别的。
- **根因**：历史上主页开关被用来控制"拦截功能"。
- **正确做法**：主页 = 模块总开关 `Features.MASTER`，具体功能开关只放功能页。
- **自查项**：
  - [ ] master 是否只做总开关，不承载具体功能？
- **关联**：H3、H6

## H3 · 功能页显示已开启但不可用

- **现象**：功能页显示"已开启"，但没有 root 权限跑不了。
- **根因**：没有考虑 master 未启用、或工作模式不支持 root。
- **正确做法**：三层都满足才显示"已开启"：`master && feature && canUseRoot`；否则显示"未启用"或 `lockedCard`（`UpdateBlockScreen`、`VersionSpoofScreen` 顶部判断）。
- **自查项**：
  - [ ] 显示条件是否三层齐全？
- **关联**：B3、B9、H6

## H4 · Toast 拦截拦不到系统 Toast

- **现象**：关键字拦截开了，系统或其他应用的 Toast 照样弹。
- **根因**：hook 的是目标进程内的 `Toast.show`，其他应用进程的 Toast 不经过这里。
- **正确做法**：写进限制说明，只承诺拦目标应用自己弹的 Toast（`MainHook` 里 Toast 守卫的注释）。
- **自查项**：
  - [ ] 能力描述是否写清范围？
- **关联**：E9

## H5 · 自启动被当成必须

- **现象**：用户以为不开自启动就完全不能用。
- **根因**：文案写成了"必须开启"。
- **正确做法**：标注"建议开启（非必需）"，规则本身在本地，不依赖守护进程。
- **自查项**：
  - [ ] 文案是"建议"而非"必须"？
- **关联**：C4

## H6 · 三层开关漏了一层

- **现象**：新增功能只有功能开关，总开关关着它也能生效。
- **根因**：新增功能时只加 feature，漏了 master 判断。
- **正确做法**：master → feature → 功能内选项三层齐全。
- **自查项**：
  - [ ] 新功能三层都判了？
- **关联**：E2、H3

## H7 · 删除类操作无确认

- **现象**：清空规则、删除目标应用，点一下就没。
- **根因**：破坏性操作直接执行。
- **正确做法**：删除 / 清空 / 覆盖一律二次确认弹窗，文案说明影响。
- **自查项**：
  - [ ] 是否有 `ui.dialog` 确认？
- **关联**：A4
